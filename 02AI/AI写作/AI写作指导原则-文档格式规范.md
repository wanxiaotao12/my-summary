#  AI 写作指导原则-文档格式规范

---

## 格式规范清单

| 规范项 | 要求 |
|--------|------|
| **Markdown 语法** | 使用标准 Markdown 语法，不混用非标准扩展 |
| **标题层级** | 从 `#` 开始，不跳级（`#` → `##` → `###`） |
| **代码块** | 标注语言类型，语法高亮 |
| **表格** | 表头与表数据对齐 |
| **列表** | 同级缩进一致，嵌套不超过三级 |
| **链接** | 使用描述性锚文本，不裸放 URL |

---

## 一、Markdown 语法

- 使用标准 Markdown 语法（CommonMark）
- 不混用 HTML 标签和 Markdown 语法
- 特殊格式使用标准语法：粗体 `**文本**`、斜体 `*文本*`、行内代码 `` `代码` ``

### 反例

> 使用 HTML 的 `<b>粗体</b>` 代替 Markdown 的 `**粗体**`

### 正例

> 使用 `**粗体**`、`*斜体*`、`` `行内代码` ``

---

## 二、标题层级

- 文档标题从 `#`（一级标题）开始
- 逐级递增：`#` → `##` → `###` → `####`
- 不跳级：不允许从 `##` 直接跳到 `####`
- 同级标题语义一致，不要有的 `##` 是功能点，有的 `##` 是操作步骤

### 反例

> ```
> # 文档标题
> ## 第一章
> #### 1.1.1 小节（跳过了 ### 二级）
> ```

### 正例

> ```
> # 文档标题
> ## 第一章
> ### 1.1 小节
> #### 1.1.1 子小节
> ```

---

## 三、代码块

- 代码块必须标注语言类型，如 ````java`、````python`、````bash`
- 行内代码使用反引号包裹：`` `variableName` ``
- 较长代码（超过 10 行）添加简要说明

### 反例

> ````
> ```
> public void hello() {
>   System.out.println("hi");
> }
> ```
> ````
> （没有标注语言类型）

### 正例

> ````
> ```java
> public void hello() {
>   System.out.println("hi");
> }
> ```
> ````
> （标注了 `java`）

---

## 四、表格

- 表头与内容对齐，使用 Markdown 表格语法
- 表格适合展示对比、枚举、配置项等结构化内容
- 表格过宽时拆分为多个表格

### 反例

> 用纯文本列举配置项，读者难以快速对比

### 正例

> | 配置项 | 类型 | 默认值 | 说明 |
> |--------|------|--------|------|
> | timeout | int | 30 | 请求超时时间（秒） |
> | retry | int | 3 | 重试次数 |

---

## 五、列表

- 有序列表用于有先后顺序的步骤
- 无序列表用于并列项、无顺序要求的枚举
- 同级缩进一致，嵌套不超过三级
- 列表项之间保持空行提高可读性

### 反例

> 1. 第一步
> 2. 第二步的
>    子步骤a
>     子步骤b（缩进不一致）

### 正例

> 1. 第一步
> 2. 第二步
>    1. 子步骤 A
>    2. 子步骤 B

---

## 六、链接

- 使用描述性锚文本，如 `[文档编写规范](./规范.md)`
- 不裸放 URL，如 `https://example.com/doc`
- 必须放裸 URL 时用反引号包裹：`` `https://example.com` ``

### 反例

> 参考 https://example.com/doc 了解更多

### 正例

> 参考 [文档编写规范](./规范.md) 了解更多

---

## 六、分隔线

- 不建议使用分隔线 `---`
- 章节之间靠标题区分即可，分隔线没有信息增量
- 如果滥用反而增加视觉噪音

### 反例

> 在每个 `###` 小节前都加分隔线，视觉噪音过大

### 正例

> 不使用分隔线，靠 `##` 标题自然区分章节
