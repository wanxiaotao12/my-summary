# 快速熟悉现有系统方法论

> 版本：V1.0
> 定位：高级技术专家视角的系统化方法论
> 目标：建立可复用的认知框架，实现"任何系统7天内具备独立工作能力"

---

## 一、方法论总纲

### 1.1 核心原则

```
┌─────────────────────────────────────────────────────────────────┐
│                        方法论四原则                              │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│   自顶向下      先整体后局部，先骨架后血肉                        │
│                                                                 │
│   业务优先      业务驱动技术，理解业务才能理解技术                 │
│                                                                 │
│   主干先行      抓住核心链路，不求面面俱到                        │
│                                                                 │
│   验证闭环      输出倒逼输入，实践检验认知                        │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 1.2 认知模型：三层金字塔

```
                    ┌─────────────┐
                    │   Why 层    │  业务价值、用户诉求
                    │  (业务层)   │  解决什么问题？为谁解决？
                    ├─────────────┤
                    │   What 层   │  系统能力、架构设计
                    │  (系统层)   │  提供什么能力？如何组织？
                    ├─────────────┤
                    │   How 层    │  技术实现、工程细节
                    │  (工程层)   │  如何实现？如何运维？
                    └─────────────┘
```

**认知规律**：
- 自顶向下理解：Why → What → How
- 自底向上验证：How → What → Why
- 每一层都要形成闭环

### 1.3 时间框架

| 阶段 | 时间 | 目标 | 关键产出 |
|------|------|------|----------|
| **认知期** | Day 1-2 | 建立系统全貌认知 | 架构草图、业务流程图 |
| **理解期** | Day 3-5 | 掌握核心实现细节 | 核心链路追踪、数据模型 |
| **验证期** | Day 6-7 | 实践检验并固化 | 完成小需求、输出文档 |

## 二、认知期：建立全貌（Day 1-2）

### 2.1 核心目标

> 在脑海中建立系统的"全景地图"，知道"系统是什么"、"解决什么问题"、"由什么组成"

### 2.2 方法：五问法

```
问题1：系统解决什么问题？     → 业务价值
问题2：谁在使用这个系统？     → 用户画像
问题3：核心业务流程是什么？   → 业务主线
问题4：系统由哪些部分组成？   → 架构边界
问题5：关键数据如何流转？     → 数据流向
```

### 2.3 执行策略

#### 策略一：信息来源优先级

```
高价值来源                    低价值来源
    ├─ 技术负责人/老员工访谈        ├─ 过时的文档
    ├─ 系统演示                    ├─ 无关的历史代码
    ├─ 架构图/设计文档              ├─ 冗余的配置
    ├─ 代码仓库结构                └─ 陈旧的注释
    ├─ 运行中的系统
    └─ 监控/日志
```

#### 策略二：访谈技巧

**访谈准备**：
- 提前准备问题清单
- 问题要具体、有针对性
- 控制在30-60分钟内

**访谈问题模板**：

| 维度 | 问题 |
|------|------|
| 业务 | "这个系统最核心的功能是什么？用户最常用的操作是什么？" |
| 架构 | "系统有哪些核心模块？它们之间怎么交互？" |
| 数据 | "最重要的数据是什么？数据怎么流转的？" |
| 难点 | "系统最复杂的地方在哪里？最容易出问题的是什么？" |
| 建议 | "如果重新设计，哪些地方可以改进？" |

#### 策略三：快速信息收集

**代码仓库扫描**（5分钟内完成）：
```bash
# 1. 项目类型判断
ls -la                          # 查看项目结构
cat pom.xml | head -50          # Maven依赖（Java）
cat package.json                # NPM依赖（Node）

# 2. 模块划分
tree -L 2 -d                    # 目录结构

# 3. 核心入口
grep -r "@SpringBootApplication\|@Controller\|main(" --include="*.java" -l

# 4. 配置文件
find . -name "*.yml" -o -name "*.properties" -o -name "*.yaml" | head -10
```

**系统运行感知**：
- 访问各环境，体验系统功能
- 查看监控大盘，了解系统健康度
- 翻阅近期告警，了解常见问题

### 2.4 产出物

**必须产出**：

1. **系统架构草图**（手绘即可）
   - 核心系统/模块
   - 系统间调用关系
   - 上游依赖/下游被调

2. **核心业务流程图**
   - 端到端主流程
   - 关键决策点
   - 涉众角色

3. **关键信息清单**
   - 环境地址和账号
   - 关键联系人
   - 重要文档链接

## 三、理解期：深入细节（Day 3-5）

### 3.1 核心目标

> 理解系统"如何实现"，掌握核心链路的代码逻辑和数据模型

### 3.2 方法：链路追踪法

```
┌─────────────────────────────────────────────────────────────────┐
│                        链路追踪法                                │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│   选择核心场景 → 从入口追踪 → 逐层深入 → 记录关键节点              │
│                                                                 │
│   入口：API接口 / 消息消费 / 定时任务                             │
│   追踪：调用链路 / 数据变更 / 状态流转                            │
│   记录：核心类 / 关键方法 / 重要配置                              │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 3.3 执行策略

#### 策略一：选择追踪场景

**选择标准**：
- 使用频率最高
- 业务价值最大
- 涉及系统最多

**常见核心场景**：
- 用户注册/登录
- 核心业务操作（下单、支付、发布等）
- 数据同步/处理

#### 策略二：代码追踪技巧

**入口识别**：
```bash
# HTTP接口入口
grep -r "@RequestMapping\|@GetMapping\|@PostMapping" --include="*.java" -l

# 消息消费入口
grep -r "@RabbitListener\|@KafkaListener\|@RocketMQMessageListener" --include="*.java" -l

# 定时任务入口
grep -r "@Scheduled\|@XxlJob" --include="*.java" -l
```

**调用链追踪**：
- IDE跳转：Ctrl+点击 / Cmd+点击
- 调用层次：Call Hierarchy（Ctrl+Alt+H）
- 类结构：Structure视图（Alt+7）
- 继承关系：Type Hierarchy（Ctrl+H）

**关键节点识别**：
- 外部服务调用（RPC/HTTP）
- 数据库操作（DAO/Repository）
- 缓存操作（Redis）
- 消息发送（MQ）
- 状态变更（状态机）

#### 策略三：数据模型理解

**快速理解数据库设计**：
```bash
# 导出表结构
mysqldump -u user -p --no-data database > schema.sql

# 或使用工具生成ER图
# DBeaver / Navicat / MySQL Workbench
```

**核心表识别**：
- 数据量最大
- 外键关联最多
- 业务命名核心（order、user、product等）

**实体类与表的映射**：
```bash
# 找到实体类
find . -name "*Entity.java" -o -name "*DO.java" -o -name "*PO.java"

# 查看ORM映射
find . -name "*Mapper.xml" -path "*/mapper/*"
```

#### 策略四：配置与依赖理解

**关键配置项**：
- 数据源配置
- 中间件配置（Redis、MQ等）
- 外部服务地址
- 业务开关配置

**依赖分析**：
```bash
# Maven依赖树
mvn dependency:tree

# 查看直接依赖
cat pom.xml | grep -A 5 "<dependencies>"
```

### 3.4 产出物

**必须产出**：

1. **核心链路代码追踪图**
   - 入口 → 处理 → 存储 → 返回
   - 标注关键类和方法

2. **数据模型图**
   - 核心表及关系
   - 关键字段说明

3. **技术栈清单**
   - 框架版本
   - 中间件版本
   - 外部依赖

## 四、验证期：实践固化（Day 6-7）

### 4.1 核心目标

> 通过实践验证理解，通过输出固化认知

### 4.2 方法：输出倒逼输入

```
┌─────────────────────────────────────────────────────────────────┐
│                      输出倒逼输入法                              │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│   学习 → 复述 → 修正 → 实践 → 文档化                             │
│                                                                 │
│   复述：向他人讲解，发现理解偏差                                  │
│   实践：完成需求/修复bug，验证理解                                │
│   文档：整理笔记，形成知识沉淀                                    │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 4.3 执行策略

#### 策略一：实践验证

**最小可行验证**：
1. 本地启动系统，跑通主流程
2. 修复一个小bug
3. 完成一个小需求（如加字段、改文案）

**验证清单**：
- [ ] 能独立启动本地环境
- [ ] 能找到代码位置
- [ ] 能修改代码并验证效果
- [ ] 能查看日志定位问题

#### 策略二：复述确认

**向导师/同事复述**：
- 系统是做什么的
- 核心架构是什么
- 关键流程怎么实现
- 技术难点在哪里

**记录反馈**：
- 理解偏差点
- 遗漏的重要信息
- 建议深入了解的点

#### 策略三：文档沉淀

**必写文档**：

1. **学习笔记**
   - 个人理解
   - 关键知识点
   - 问题记录

2. **架构图**
   - 系统架构图
   - 部署架构图
   - 核心流程图

3. **FAQ**
   - 常见问题及答案
   - 遇到的坑及解决方案

### 4.4 产出物

**必须产出**：

1. **学习笔记**（Markdown格式）
2. **架构图**（至少2张：系统架构、核心流程）
3. **FAQ文档**（至少10个问题）

## 五、高级技巧

### 5.1 信息获取困难时的策略

| 困难 | 策略 |
|------|------|
| 文档缺失或过时 | 从代码逆向，先跑起来再理解 |
| 找不到人问 | 查Git历史，看谁改过代码；查Jira，看谁处理过问题 |
| 代码太复杂 | 抓主干，先理解核心流程，细节后续补充 |
| 系统太大 | 划分边界，先理解自己负责的模块 |

### 5.2 快速定位代码的技巧

**场景 → 代码映射表**：

| 场景 | 定位方法 |
|------|----------|
| 页面功能 | URL → Controller → Service |
| 定时任务 | @Scheduled注解 → 方法名 |
| 消息消费 | @RabbitListener → 队列名 → 方法 |
| 数据变更 | 表名 → Mapper/Repository → 调用方 |
| 接口调用 | 接口名 → Feign Client → 实现类 |

**搜索技巧**：
```bash
# 按关键词搜索
grep -r "关键词" --include="*.java" -n

# 按文件名搜索
find . -name "*关键词*"

# 按类名搜索（IDE更方便）
# Ctrl+N / Cmd+O

# Git历史搜索
git log --grep="关键词" --oneline
```

### 5.3 理解复杂逻辑的技巧

**方法一：画图**
- 流程图：理解业务逻辑
- 时序图：理解调用关系
- 状态图：理解状态流转

**方法二：调试**
- 断点追踪：关键节点打断点
- 日志追踪：增加日志观察变量
- Arthas：动态追踪线上方法

**方法三：测试**
- 阅读单元测试，理解预期行为
- 编写测试用例，验证理解

### 5.4 避免常见陷阱

| 陷阱 | 表现 | 对策 |
|------|------|------|
| 陷入细节 | 钻牛角尖，忽略整体 | 设定时间限制，先过再回 |
| 只看不动 | 只读代码不实践 | 边看边调试，动手验证 |
| 孤立学习 | 不与团队交流 | 主动提问，定期同步 |
| 没有记录 | 看过就忘 | 边学边记，整理文档 |
| 求全责备 | 想要掌握所有细节 | 抓核心，渐进深入 |

## 八、总结

### 8.1 方法论核心要点

```
┌─────────────────────────────────────────────────────────────────┐
│                                                                 │
│   一个模型：三层金字塔（业务层-系统层-工程层）                     │
│                                                                 │
│   四个原则：自顶向下、业务优先、主干先行、验证闭环                 │
│                                                                 │
│   三个阶段：认知期（Day 1-2）→ 理解期（Day 3-5）→ 验证期（Day 6-7）│
│                                                                 │
│   一个目标：7天内具备独立工作能力                                 │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 8.2 成功关键因素

1. **主动学习**：不等不靠，主动获取信息
2. **善于提问**：问题具体，有的放矢
3. **勤于记录**：边学边记，形成积累
4. **勇于实践**：动手验证，加深理解
5. **及时反馈**：复述确认，修正偏差

### 8.3 持续精进

熟悉系统不是一次性工作，而是持续过程：

- **日常积累**：遇到问题深挖根因
- **定期复盘**：更新架构图和文档
- **知识分享**：向他人讲解，教学相长
- **关注演进**：跟踪系统变更，保持认知更新

---

> 💡 **最后建议**：方法论是工具，不是教条。根据实际情况灵活调整，找到适合自己的节奏。核心是建立系统化的认知框架，而非机械执行步骤。
