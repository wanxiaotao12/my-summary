> 这是三篇 Dockerfile 文档的第三篇，聚焦「怎么写好」。学完 [01-概念与指令.md](./01-概念与指令.md) 和 [02-构建与运行.md](./02-构建与运行.md) 后，这里的模板可直接套用，优化技巧可帮助构建更快、镜像更小，FAQ 可快速排错。

## 语言实战模板

以下是 Python、Java、Node.js 三种语言的完整 Dockerfile 模板，可直接复制到项目中使用。

### Python 应用

```dockerfile
FROM python:3.9-slim

WORKDIR /app

COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt

COPY . .

EXPOSE 8000

CMD ["python", "app.py"]
```

**要点**：先 COPY 依赖文件再 `pip install`，利用构建缓存——只有 `requirements.txt` 变更时才重装依赖。

### Java 应用（多阶段构建）

```dockerfile
FROM maven:3.8-openjdk-17 AS build
WORKDIR /build
COPY pom.xml .
COPY src ./src
RUN mvn clean package -DskipTests

FROM openjdk:17-slim
WORKDIR /app
COPY --from=build /build/target/app.jar .

EXPOSE 8080

CMD ["java", "-jar", "app.jar"]
```

> Maven 默认打包出 `＜artifactId＞-＜版本＞.jar`（如 `myapp-1.0.jar`）。示例用 `app.jar` 是简写，实际项目需在 `pom.xml` 配置 `<build><finalName>app</finalName></build>`。

### Node.js 应用

```dockerfile
FROM node:18-alpine

WORKDIR /app

COPY package*.json ./
RUN npm ci --only=production

COPY . .

EXPOSE 3000

CMD ["node", "index.js"]
```

**要点**：`npm ci --only=production` 只装生产依赖，跳过 devDependencies，减小体积。

## 优化技巧

### 1. 减小镜像体积

```dockerfile
# 安装后清理缓存
RUN apt-get update && apt-get install -y curl && rm -rf /var/lib/apt/lists/*

# pip 不用缓存
RUN pip install --no-cache-dir -r requirements.txt

# npm 只装生产依赖
RUN npm ci --only=production
```

**此外**：优先选 `slim` 或 `alpine` 标签的基础镜像，体积比 `latest` 小很多。

### 2. 利用构建缓存

Docker 按指令顺序缓存：前面的指令未变时直接复用缓存。把**变化频率低**的文件放前面：

```dockerfile
# ✅ 正确：依赖文件先 COPY，源码后 COPY
COPY requirements.txt .
RUN pip install -r requirements.txt
COPY . .

# ❌ 错误：先 COPY 所有文件，每次改一行代码都重装依赖
COPY . .
RUN pip install -r requirements.txt
```

### 3. 使用 .dockerignore

排除不需要进入镜像的文件，加快构建速度：

```
.git
.gitignore
README.md
.env
*.log
node_modules
__pycache__
```

### 4. 镜像标签策略

避免使用 `latest` 标签——它的含义"最近一次不带标签的构建"，你不知道具体是哪个版本。推荐：

```bash
docker build -t my-app:v1.0.0 .     # 语义化版本
docker build -t my-app:20260101 .   # 日期版本
```

### 5. 合并 RUN 指令

```dockerfile
# ✅ 推荐：一层
RUN apt-get update && apt-get install -y curl vim && rm -rf /var/lib/apt/lists/*

# ❌ 不推荐：三层
RUN apt-get update
RUN apt-get install -y curl
RUN apt-get install -y vim
```

## 常见问题（FAQ）

### Q1：COPY 的 `.` 到底代表什么？

`.` 代表**当前 WORKDIR**。如果设置了 `WORKDIR /app`，那么 `COPY . .` 等价于 `COPY . /app`。如果没有设置 WORKDIR，`.` 就是根目录 `/`。

### Q2：CMD 和 ENTRYPOINT 有什么区别？

| | CMD | ENTRYPOINT |
|---|-----|------------|
| 被 `docker run` 覆盖？ | 会 | 不会 |
| 典型用法 | 默认启动命令 | 固定入口，CMD 做附加参数 |

一句话：CMD 是"建议"，ENTRYPOINT 是"决定"。

### Q3：构建太慢怎么排查？

1. 检查 COPY 顺序——变化频率高的文件是不是放太前面了（见上文「利用构建缓存」）
2. 检查 `.dockerignore`——是不是把 `node_modules` 之类的大目录也复制进去了
3. 检查基础镜像——`latest` 标签可能比 `slim`/`alpine` 大几倍
4. 用 `docker build --no-cache` 验证是不是缓存出了问题

### Q4：EXPOSE 写了端口，为什么外面访问不到？

EXPOSE 只是"备注"，不真正开通端口。必须运行时加 `-p`：

```bash
docker run -p 8000:8000 my-image
```

### Q5：容器停了数据就没了？

默认是的。要让数据持久化，用数据卷：

```bash
docker run -v /host/data:/app/data my-image
```

或 docker-compose 中配置 `volumes`。不一定需要在 Dockerfile 中写 VOLUME 指令——`-v` 和 `volumes:` 不依赖它。

### Q6：多个 CMD 哪个生效？

只有**最后一条**。Dockerfile 中前面的 CMD 会被静默丢弃。

### Q7：多阶段构建中能有几个阶段？

任意多个。常见的是两个（编译 + 运行），也可以更多（如多语言混合编译）。每个阶段可以独立选择基础镜像。

### Q8：`docker build` 的上下文（`.`）是什么意思？

不是"Dockerfile 所在的目录"，而是"构建时发给 Docker daemon 的文件范围"。COPY 只能复制上下文内的文件，所以通常设为项目根目录。
