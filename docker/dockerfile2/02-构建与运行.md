# 构建与运行（使用指南）

> 这是三篇 Dockerfile 文档的第二篇，聚焦「怎么跑」。如果还没写 Dockerfile，请先阅读 [01-概念与指令.md](./01-概念与指令.md)；实战模板、优化技巧与常见问题见 [03-最佳实践.md](./03-最佳实践.md)。

## 使用环境

| 环境 | 说明 |
|------|------|
| 本地电脑 | 安装 Docker Desktop，用于本地开发和测试 |
| 服务器 | Linux 服务器上安装 Docker，用于部署 |
| CI/CD 流水线 | Jenkins、GitLab CI 等工具中自动构建 |

**前提**：先安装 Docker。

## 两种场景

写好 Dockerfile 后跑起来分两种场景：

| 场景 | 工具 | 适用情况 |
|------|------|----------|
| 单容器 | `docker` 命令 | 只跑一个应用，`docker build` + `docker run` |
| 多容器 | `docker-compose` | 多个服务（如 web + 数据库），yml 文件统一管理 |

两种场景共用同一份 Dockerfile，区别只在怎么启动。

---

## 场景一：单容器（docker 命令）

### 第一步：构建镜像

命令格式（方括号内为可选）：

```
docker build [-f <文件>] -t <镜像名>:<标签> <构建上下文路径>
```

| 组成部分 | 必填 | 说明 |
|----------|------|------|
| `-f <文件>` | 可选 | 文件名不叫 `Dockerfile` 时指定（如 `-f Dockerfile.prod`） |
| `-t` | 强烈建议 | 给镜像起名和版本号，不填则只能用 ID 引用 |
| `<镜像名>:<标签>` | 强烈建议 | 如 `my-app:v1.0` |
| `<构建上下文路径>` | 必填 | `.` 表示当前目录 |

**填写顺序**：先想好镜像名（`镜像名:标签`），再指定上下文路径；文件名非默认时再加 `-f`。

```bash
# 默认文件名
docker build -t my-app:v1.0 .

# 指定文件名
docker build -f Dockerfile.prod -t my-app:prod .
#            ↑ 指定文件        ↑ 镜像名         ↑ 上下文
```

### 第二步：查看镜像

```bash
docker images
```

### 第三步：运行容器

```bash
docker run -p 8000:8000 my-app:v1.0
```

| 参数 | 必填 | 说明 |
|------|------|------|
| `-p 8000:8000` | 按需 | 端口映射（宿主机:容器） |
| `my-app:v1.0` | 必填 | 镜像名和标签 |

**常用可选参数**：

| 参数 | 说明 |
|------|------|
| `-d` | 后台运行（不加则占当前终端） |
| `--name my-container` | 给容器起名字 |

**完整操作**：

```bash
# 后台运行并命名
docker run -d --name my-app -p 8000:8000 my-app:v1.0

# 查看运行中的容器
docker ps

# 查看日志
docker logs my-app

# 停止容器
docker stop my-app
```

## 场景二：多容器（docker-compose）

多个服务（如 web + 数据库）时，手工一个个起容器很麻烦。docker-compose 用一个 yml 文件描述所有服务，一条命令全拉起来。

### 前提

新版本 Docker Desktop 已内置 `docker compose`（空格，非连字符）；老版本需单独安装 `docker-compose`。

### 第一步：编写 docker-compose.yml

在 Dockerfile 所在目录新建 `docker-compose.yml`。以下为 web + MySQL 的最小示例：

```yaml
services:
  web:                        # 你的应用
    build: .                  # 用当前目录的 Dockerfile 构建
    ports:
      - "8000:8000"           # 宿主机:容器
    depends_on:
      - db                    # 依赖 db，compose 先启动 db

  db:                         # 数据库（用现成镜像，无需 Dockerfile）
    image: mysql:8.0
    environment:
      MYSQL_ROOT_PASSWORD: 123456
    volumes:
      - db_data:/var/lib/mysql     # 数据持久化

volumes:
  db_data:                    # 声明数据卷
```

### 关键字段

| 字段 | 作用 |
|------|------|
| `services` | 列出所有服务 |
| `build` | 用 Dockerfile 构建（`.` = 当前目录） |
| `image` | 直接用现成镜像 |
| `ports` | 端口映射 |
| `depends_on` | 声明依赖，被依赖的先启动 |
| `environment` | 传环境变量 |
| `volumes` | 数据卷，容器删了数据还在 |

> `build` 和 `image` 二选一——`build` 打包自己的应用，`image` 用官方现成镜像。

### 第二步：启动

```bash
docker compose up -d
#          ↑ -d：后台运行
```

compose 自动构建 web 镜像、拉取 MySQL 镜像，分别启动并连到同一网络。

### 第三步：查看与停止

```bash
docker compose ps              # 查看各服务状态
docker compose logs web        # 查看某服务日志
docker compose down            # 停止并移除所有服务（数据卷保留）
```

| 命令 | 作用 |
|------|------|
| `docker compose up -d` | 构建并后台启动所有服务 |
| `docker compose ps` | 查看服务容器状态 |
| `docker compose logs <服务名>` | 查看某服务日志 |
| `docker compose down` | 停止并移除（数据卷不删） |
