# Docker Compose 配置文件

## docker-compose.yml 文件结构

先看一个完整的示例：

```yaml
version: '3.8'

services:
  web:
    image: nginx:latest
    ports:
      - "80:80"
    depends_on:
      - app
    networks:
      - app-network

  app:
    build: .
    environment:
      - DB_HOST=db
    depends_on:
      - db
    networks:
      - app-network

  db:
    image: mysql:8.0
    environment:
      MYSQL_ROOT_PASSWORD: root123
    volumes:
      - db-data:/var/lib/mysql
    networks:
      - app-network

networks:
  app-network:
    driver: bridge

volumes:
  db-data:
```

一个 `docker-compose.yml` 文件由三个顶级键组成：

| 键 | 是否必填 | 说明 |
|----|----------|------|
| `services` | 必填 | 定义应用的所有服务（每个服务是一个容器） |
| `networks` | 可选 | 定义服务间通信的网络 |
| `volumes` | 可选 | 定义持久化数据卷 |

下面逐个讲解每个顶级键的详细配置。

## services（服务）

`services` 下每个子键是一个服务的名称，服务名即容器名的一部分。

```yaml
services:
  <服务名>:
    image: <镜像名:标签>      # 使用已有镜像
    build: <构建上下文路径>    # 或从 Dockerfile 构建
    ports:                    # 端口映射
      - "<宿主机端口>:<容器端口>"
    environment:              # 环境变量
      - KEY=VALUE
    volumes:                  # 数据卷挂载
      - <宿主机路径>:<容器路径>
    depends_on:               # 依赖的其他服务
      - <依赖的服务名>
```

### 常用配置项

| 配置项 | 是否必填 | 说明 |
|--------|----------|------|
| `image` | 与 build 二选一 | 指定使用的镜像。若本地不存在，启动时自动从仓库拉取 |
| `build` | 与 image 二选一 | 构建镜像，可以是字符串（Dockerfile 所在目录）或对象 |
| `container_name` | 可选 | 指定容器名称。不指定则自动生成 `<项目名>_<服务名>_<序号>` |
| `ports` | 按需 | 端口映射，将容器端口暴露到宿主机 |
| `expose` | 可选 | 仅声明容器对外暴露的端口（不映射到宿主机，仅供其他服务访问） |
| `environment` | 按需 | 设置环境变量，支持列表或字典格式 |
| `env_file` | 按需 | 从文件加载环境变量 |
| `volumes` | 按需 | 挂载数据卷或目录 |
| `depends_on` | 按需 | 声明依赖关系，控制启动顺序 |
| `networks` | 按需 | 指定服务加入的网络 |
| `restart` | 可选 | 重启策略 |
| `command` | 可选 | 覆盖镜像默认的启动命令 |
| `entrypoint` | 可选 | 覆盖镜像默认的入口点 |
| `healthcheck` | 可选 | 健康检查配置 |

#### image

指定使用的镜像。

```yaml
services:
  web:
    image: nginx:1.25-alpine    # 指定版本（推荐）
  app:
    image: myapp:latest         # 使用 latest（不推荐，环境可能不一致）
```

#### build

构建镜像，有两种写法：

```yaml
# 写法一：字符串，指定 Dockerfile 所在目录（相对于 docker-compose.yml 文件）
services:
  web:
    build: .                    # 使用当前目录（docker-compose.yml 所在目录）的 Dockerfile

# 写法二：对象，可指定 Dockerfile 文件名和构建参数
services:
  web:
    build:
      context: ./app            # 构建上下文目录（相对于 docker-compose.yml 文件，./ 表示相对路径，可省略，写成 app 也可以）
      dockerfile: Dockerfile.dev  # 指定 Dockerfile 文件名（默认 Dockerfile）
```

#### container_name

指定容器名称。不指定时自动生成，格式为 `<项目名>_<服务名>_<序号>`：

- 项目名：`docker-compose.yml` 所在目录名
- 服务名：`services` 下的子键名
- 序号：从 1 开始自动递增

```yaml
services:
  web:
    image: nginx
    container_name: my-nginx    # 容器名固定为 my-nginx
```

#### ports

端口映射，将容器端口暴露到宿主机。

```yaml
services:
  web:
    ports:
      - "8080:80"               # 宿主机 8080 -> 容器 80
      - "443:443"               # 指定协议默认 tcp
      - "53:53/udp"             # 指定 udp 协议
      - "3000-3001:3000-3001"   # 端口范围映射
```

#### expose

仅声明容器对外暴露的端口，**不映射到宿主机**，仅供同一网络内的其他服务访问。

```yaml
services:
  web:
    expose:
      - "3000"                  # 其他服务可通过 3000 端口访问，宿主机无法直接访问
```

#### environment

设置环境变量，支持列表或字典两种格式：

```yaml
# 列表格式
services:
  db:
    environment:
      - MYSQL_ROOT_PASSWORD=root123
      - MYSQL_DATABASE=mydb

# 字典格式
services:
  db:
    environment:
      MYSQL_ROOT_PASSWORD: root123
      MYSQL_DATABASE: mydb
```

#### env_file

从文件加载环境变量，适合管理敏感信息：

```yaml
services:
  db:
    env_file:
      - .env                    # 加载 .env 文件中的所有变量
      - .env.db                 # 可指定多个文件
```

#### volumes

挂载数据卷或目录，有两种方式：

```yaml
volumes:
  db-data:                      # 在顶级 volumes 中声明命名卷

services:
  db:
    volumes:
      - db-data:/var/lib/mysql          # 命名卷（Docker 管理存储路径）
      - ./data:/var/lib/mysql           # 绑定挂载（指定宿主机具体路径）
      - ./config.yml:/etc/config.yml:ro # 挂载单个文件，只读模式
```

#### depends_on

声明依赖关系，控制服务启动顺序：

```yaml
services:
  app:
    depends_on:
      - mysql                   # mysql 先启动，app 再启动
      - redis
```

配合 `healthcheck` 可等待依赖服务完全就绪：

```yaml
services:
  app:
    depends_on:
      mysql:
        condition: service_healthy  # 等 mysql 健康检查通过后再启动

  mysql:
    image: mysql:8.0
    healthcheck:
      test: ["CMD", "mysqladmin", "ping", "-h", "localhost"]
      interval: 10s
      retries: 5
```

#### networks

指定服务加入的网络，同一网络内的服务可通过服务名互相访问：

```yaml
services:
  web:
    networks:
      - app-network             # 加入 app-network 网络
      - frontend-network        # 可加入多个网络

networks:
  app-network:
    driver: bridge
  frontend-network:
    driver: bridge
```

#### command

覆盖镜像默认的启动命令：

```yaml
services:
  web:
    image: nginx
    command: nginx -g "daemon off;"    # 字符串格式
    command: ["nginx", "-g", "daemon off;"]  # 列表格式
```

#### entrypoint

覆盖镜像默认的入口点：

```yaml
services:
  web:
    image: myapp
    entrypoint: /custom-entrypoint.sh
    entrypoint: ["/custom-entrypoint.sh", "--arg1"]  # 列表格式
```

#### healthcheck

健康检查配置，用于检测容器内的服务是否正常运行：

```yaml
services:
  web:
    image: nginx
    healthcheck:
      test: ["CMD", "curl", "-f", "http://localhost"]  # 检查命令
      interval: 30s             # 检查间隔
      timeout: 10s              # 超时时间
      retries: 3                # 连续失败次数判定为不健康
      start_period: 40s         # 启动后等待时间（初始化阶段不检查）
```

### restart 重启策略

控制容器退出后是否自动重启：

| 值 | 说明 |
|----|------|
| `no` | 不自动重启（默认） |
| `always` | 任何情况下都重启 |
| `on-failure` | 仅在退出码非零时重启（即容器异常退出时重启） |
| `unless-stopped` | 始终重启，除非手动停止 |

```yaml
services:
  web:
    restart: unless-stopped     # 推荐用于生产环境
```

## networks（网络）

定义服务间通信的网络。同一网络内的服务可通过服务名互相访问。

```yaml
networks:
  app-network:
    driver: bridge              # 网络驱动，默认为 bridge
  frontend-network:
    driver: bridge
```

| 驱动 | 说明 |
|------|------|
| `bridge` | 默认驱动，适用于独立运行的容器间通信 |
| `host` | 直接使用宿主机网络，容器端口与宿主机端口相同 |
| `none` | 无网络，需手动配置 |

服务通过 `networks` 配置项加入网络（详见 [services 配置项](#networks)）。

## volumes（数据卷）

定义持久化数据卷，在顶级声明后供服务使用。

```yaml
volumes:
  db-data:                      # 命名卷，Docker 自动管理存储路径
  cache-data:
    driver: local               # 可指定驱动（默认 local）
```

| 类型 | 说明 | 示例 |
|------|------|------|
| 命名卷 | Docker 管理存储路径，推荐用于数据库等持久化数据 | `db-data:/var/lib/mysql` |
| 绑定挂载 | 指定宿主机具体路径，适合挂载配置文件或代码 | `./data:/var/lib/mysql` |

服务通过 `volumes` 配置项使用数据卷（详见 [services 配置项](#volumes)）。
