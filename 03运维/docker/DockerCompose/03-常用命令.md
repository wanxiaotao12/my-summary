# Docker Compose 常用命令

注意：以下命令均在 `docker-compose.yml` 文件所在目录执行。

## 命令格式

```
docker compose [选项] <命令> [服务名]
```

**常用选项**：

| 选项 | 说明 |
|------|------|
| `-f` | 指定配置文件（默认 `docker-compose.yml`） |
| `-p` | 指定项目名（用于生成容器、网络、卷的前缀） |

**常用命令**：

| 命令 | 说明 |
|------|------|
| `up` | 创建并启动服务容器 |
| `down` | 停止并移除容器、网络 |
| `start` / `stop` / `restart` | 启动 / 停止 / 重启服务 |
| `ps` | 查看服务状态 |
| `logs` | 查看日志 |
| `exec` | 在容器中执行命令 |
| `build` | 构建镜像 |
| `pull` | 拉取镜像 |

**服务名**：可选。指定时只对单个服务生效；不指定则对所有服务生效。

## 启动

启动服务容器。`up` 会创建并启动容器，`start` 仅启动已停止的容器。

```bash
# 创建并启动所有服务（-d 表示后台运行，不占用当前终端）
docker compose up -d

# 强制重新构建镜像并启动（--build 强制重新构建镜像）
docker compose up -d --build

# 启动指定服务
docker compose up -d <服务名>

# 启动已停止的容器（不重新创建）
docker compose start

# 启动指定服务的已停止容器
docker compose start <服务名>
```

`up` 与 `start` 的区别：
- `up`：创建并启动容器
  - 若容器不存在：
    - 获取镜像：配置了 `build` 则构建，配置了 `image` 则拉取
    - 基于镜像创建容器
    - 启动容器
  - 若容器已存在：直接启动
- `start`：仅启动已存在的已停止容器，不重新创建

`up -d` 与 `up -d --build` 的区别：
- `up -d`：若镜像已存在则直接使用，不会重新构建
- `up -d --build`：强制重新构建镜像
  - 适用于代码或 Dockerfile 变更后需要更新镜像的场景
  - 执行后会停止并删除旧容器，用新镜像创建新容器
  - 旧镜像不会自动删除，会变成悬空镜像（无标签），可用 `docker image prune` 清理

## 构建镜像

根据 Dockerfile 构建服务镜像。仅适用于在 `docker-compose.yml` 中配置了 `build` 的服务，若服务只配置了 `image`，则无需使用此命令。

`up` 启动时会自动构建，单独的 `build` 命令用于只构建不启动的场景，如代码变更后重新构建镜像。

```bash
# 构建所有服务的镜像
docker compose build

# 构建指定服务
docker compose build <服务名>

# 不使用缓存构建
docker compose build --no-cache
```

## 停止

停止运行中的容器。`stop` 仅停止容器不删除，`down` 停止并删除容器和网络。

```bash
# 停止所有运行中的容器（不删除）
docker compose stop

# 停止指定服务的容器
docker compose stop <服务名>

# 停止并删除所有容器和网络（卷默认保留）
docker compose down

# 停止并删除容器、网络和数据卷（加 -v 连同卷一起删除）
docker compose down -v
```

`stop` 与 `down` 的区别：
- `stop`：仅停止容器，不删除，可用 `start` 重新启动
- `down`：停止并删除容器和网络，需要重新 `up` 创建

## 重启

重启即先停止再启动容器内的进程。重启时容器和镜像都不变，不会重新创建容器，也不会重新构建或拉取镜像。

常用于：
- 应用配置变更后重新加载
- 服务异常时恢复运行

```bash
# 重启所有服务
docker compose restart

# 重启指定服务
docker compose restart <服务名>
```

## 查看状态

查看服务运行状态和日志输出。

```bash
# 查看运行中的服务
docker compose ps

# 查看服务日志
docker compose logs

# 实时跟踪日志
docker compose logs -f

# 查看指定服务的日志
docker compose logs <服务名>
```

## 执行命令

在运行中的容器内执行命令，常用于调试或进入容器交互式终端。

```bash
# 在运行的容器中执行命令
docker compose exec <服务名> <命令>

# 进入容器的交互式终端
docker compose exec -it <服务名> /bin/bash
```

## 其他命令

其他辅助命令，包括版本查看、配置校验、暂停/恢复服务等。

```bash
# 查看版本
docker compose version

# 配置校验（检查 yml 文件语法是否正确）
docker compose config

# 暂停服务
docker compose pause

# 恢复服务
docker compose unpause

# 删除服务产生的数据卷（加 -v）
docker compose down -v
```
